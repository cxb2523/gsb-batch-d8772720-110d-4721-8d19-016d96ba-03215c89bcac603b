# Changelog

This project follows [Semantic Versioning](https://semver.org/).

## [0.4.0] - 2026-08-29

**Bring your own data.** The README already said a MediaCrawler export could be fed to Prism; now there is code behind that claim.

### Added
- **`framework/importers.py`** — map any rows (CSV / JSON / list of dicts) onto the universal 5-table schema, after which the whole analysis layer runs on them unchanged
  - Presets for MediaCrawler's Xiaohongshu and Bilibili exports, with field names read off the producing code rather than guessed
  - `FieldMap` for anything else: describe your columns once
  - Author IDs are salt-hashed on import, so this is not a side door around anonymization
  - Chinese-unit counts (`1.2万`, `1.2亿`), thousands separators and `999+` are parsed; unparseable values are skipped rather than recorded as zero
- **PyPI publish workflow** (`.github/workflows/publish.yml`) using Trusted Publishing (OIDC) — no API token stored anywhere. Verifies the built wheel contains its data files and runs `prism demo` from a clean venv before publishing.
- **Animated terminal demo** (`docs/assets/demo.svg`), generated by a checked-in script

### Changed
- Documentation is now English-first throughout; `.env.template` and `.gitignore` were still commented in Chinese, and `DISCLAIMER.md` now leads with English
- Long titles in the ranking output ellipsize instead of being cut mid-word

### Fixed
- `mypy .` failed with "Duplicate module" for anyone who had run a build
- Removed an internal project name that had leaked into a Kuaishou error string

## [0.3.0] - 2026-08-22

**Platform coverage doubled**: added Douyin and Kuaishou adapters (four platforms total), repositioned as the "analysis layer above scrapers", and formalized compliance boundaries.

### Added
- **Douyin adapter** (`framework/adapters/douyin.py`): uses the app-side guest feed endpoint — no login, no QR code; supports niche keyword filtering
- **Kuaishou adapter** (`framework/adapters/kuaishou.py`)
- Per-platform field-mapping configs `config/{douyin,kuaishou}_selectors.yml`
- **Extensibility proven again**: the analysis layer written for Xiaohongshu (`collect_rate_ranking`, etc.) runs across all four platforms with zero changes

### Changed
- **Repositioned**: from "content research framework" to **the analysis layer that sits above scrapers** (updated in both README and README\_zh.md); data can come from built-in adapters or any external export
- ROADMAP fully rewritten (most items previously listed as "planned" had already shipped)
- DISCLAIMER upgraded: explicit non-commercial restriction, coverage extended to all four platforms, new **technical boundary statement** and legal references

### Removed
- **Removed all Douyin `a_bogus` signature code** (including the CLI `--sign` flag). Prism does not implement or distribute any anti-scraping signature bypass. The flag was off by default and the guest endpoint works without it; the adapter is unaffected.

### Fixed
- Documentation consistency: analysis dimensions not yet implemented (cover image analysis, paid-promotion detection) are now clearly marked as Roadmap in METHODOLOGY

## [0.2.0] - 2026-06-15

**Renamed to Prism** (platform-agnostic content research framework, Xiaohongshu as the first adapter; formerly xhs-research-skill) + end-to-end run on live data + automated cookie handling + writer/reviewer separation for second-pass review.

### Added
- **Automatic cookie decryption** (`framework/adapters/xhs_cookies.py`): reads and decrypts cookies from a macOS Chrome profile automatically — no manual export (falls back to `cookies.json` when unavailable)
- **Batch fetch** `XHSAdapter.fetch_feed`: homepage recommendation feed → per-post detail fetch for saves (the feed list only exposes likes; save count requires the detail page)
- **End-to-end demo** `examples/fetch_live.py`: auto-reads local Chrome cookies → fetches → writes to the universal 5-table schema → runs targeted analysis
- 3 regression tests (empty cookie ciphertext / fatal exception propagation in `fetch_feed` / single-item failure skip); all 11 tests pass

### Fixed (caught by writer/reviewer separation review)
- `_decrypt` raised `IndexError` on empty ciphertext (only the `'v10'` prefix present)
- `tempfile.mktemp` race condition (TOCTOU) → replaced with `mkstemp` + try-finally for explicit cleanup of connections and temp files
- `fetch_feed`'s bare `except Exception` silently swallowed fatal `RateLimiter` exceptions → now re-raises as `RuntimeError` (prevents partial data being returned on rate-limit breach)

### Verified
- Field mapping correct on live data: `likedCount` / `collectedCount` / `commentCount` / `shareCount`
- Full end-to-end run on real data: collect-rate ranking / image posts vs videos / high-frequency topics (sample omitted)

## [0.1.0] - 2026-06-15

Initial release: a Xiaohongshu content research framework skeleton ready for GitHub (cookie-independent layer 100% complete).

### Added
- **Universal 5-table schema** (entities / items / metrics / texts / features), comparable across platforms
- **XHS adapter** (`framework/adapters/xhs.py`): cookie + `__INITIAL_STATE__` parsing; parse layer as pure functions + fetch layer (exponential backoff + cookie expiry detection)
- **Compliance base** (`compliance.py`): user anonymization (salted HMAC + sensitive field removal) + rate limiting (anti-ban)
- **Config-driven** (`config/xhs_selectors.yml`): field mappings are external; platform changes only require updating the YAML
- **Targeted analysis** (`framework/analysis/xhs_insights.py`): collect-rate ranking / image posts vs videos / topic frequency
- **Docs**: README / SKILL.md / METHODOLOGY / ARCHITECTURE / CONTRIBUTING / DISCLAIMER
- **Engineering**: pyproject / LICENSE (MIT) / .gitignore / anonymized demo.db / 8 offline tests / GitHub Actions CI
